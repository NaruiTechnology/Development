Magnification Calibration to the FPGA Subtarget

The current calibration/scan data path, configured revC3 FPGA DAC/ADC wiring, and the separate FEI magnification switch-box integration gap.

Integration status: OPEN. The application currently has no outbound control path to an external FEI magnification switch box, including the FiBDb235 system. It does not send the box a magnification value or control signal. The scan FPGA path described here sends DAC-domain coordinates and dwell values only. The OBI DAC connector is not the switch-box interface.

Data path

1 · MAG CALPer-beam curve: magnification → full horizontal FOV in meters (`m_per_fov`).
2 · Applied geometryHFOV, pixel counts and corrections resolve pixel scale and map physical ROI to DAC coordinates.
3 · Scan commandHost sends the ROI/vector DAC values and dwell through Glasgow USB pipes `PQ`.
4 · Scan DAC busFPGA generates or consumes X/Y DAC codes and strobes the upstream OBI bus.

Changing a MAG CAL point alone does not alter an already-applied scan-geometry snapshot. Resolve and apply the intended geometry before scanning. Physical pixel size for the horizontal axis is HFOV divided by the number of pixels across.

Separate switch-box control path: not implemented

The scan geometry/DAC path does not close the requirement to command the FEI magnification switch box. No driver, USB/serial/network protocol, FPGA command/register, electrical output, or FiBDb235 connector/pin mapping for that box was found in the current application sources and configuration. Do not infer a signal name or connector pinout from the OBI scan bus.

Use this sequence to implement the separate interface. Steps 1–3 are required design inputs; the concrete transport and connector details must come from the FiBDb235 documentation/vendor, not from the scan bus:

  1. Acquire the authoritative interface specification. Obtain the FiBDb235 manual or vendor-confirmed interface-control document. Record exact model/revision, control mode, protocol, connector part/pin numbers, command examples, and any required interface cable or adapter.
    Gate: Do not connect or drive an undocumented pin. If the vendor does not document remote control, ask them to confirm the supported method first.
  2. Complete the electrical and operational review. Confirm signal levels/range, polarity, impedance/current, grounding/isolation, shielding, update timing, settling time, readback/acknowledgement, safe state, and microscope/software ownership. Determine how local microscope control is disabled or arbitrated so two controllers cannot fight.
    Gate: Instrument owner and electrical reviewer approve the connection and safe-state behavior before hardware tests.
  3. Define and validate the magnification mapping. Specify the source value (the actual requested microscope magnification), supported discrete/continuous values, rounding or table mapping, encoded command or voltage, tolerances, invalid-value handling, and how the box confirms its selected state. Keep this mapping separate from the MAG CAL HFOV curve; HFOV calibrates image geometry and is not automatically the switch-box command.
    Gate: Review a mapping table with the instrument owner and test boundary, unsupported, and representative values without connecting hardware.
  4. Add a dedicated interface adapter. Create a backend/service abstraction such as MagnificationController.setMagnification(value) with explicit transport configuration, input validation, timeout, bounded retry policy, acknowledgement/readback, and structured unavailable/error results. Implement the adapter only for the vendor-approved transport. Do not append magnification data to raster/vector pixel commands or reuse OBI DAC pins unless the vendor explicitly specifies that electrical interface.
  5. Connect the UI and scan lifecycle. Establish one source of truth for the selected/actual operating magnification. On an operator change, validate and send the mapped command, wait for acknowledgement and the documented settle interval, then mark the setting current. Block or visibly refuse scans when the external box is required but not confirmed. Show requested value, confirmed value, and communication/fault status; never silently fall back to the last value.
  6. Test without the instrument. Add unit tests for value-to-command mapping, protocol framing/checksums if applicable, invalid values, timeouts, retries, acknowledgement mismatch, disconnected device, and concurrent/manual ownership. Add a fake adapter so scan workflow tests prove that a scan cannot start before confirmation when box control is required.
  7. Commission in stages. First test the interface with the beam disabled and a vendor-approved test method. Verify connector continuity and measured levels with appropriate isolated equipment; command a small set of known magnifications and compare box readback/display with the requested values. Then test settling and scan interlocks at low risk. Record instrument model/revision, adapter/cable, configuration, measured results, rollback procedure, and approver.
    Gate: Do not enable normal scanning until command/readback, fault handling, ownership, and safe recovery have passed instrument-owner acceptance.
  8. Publish the verified wiring and support record. Replace the “unknown” items in this reference with the vendor-confirmed connector table, electrical levels, protocol, mapping, and tested hardware/software revisions. Keep the existing OBI scan DAC table separately labeled. Update localized help only after those details are verified.

Minimum interface contract to implement

setMagnification(requestedValue) → confirmedValue | explicit error
preconditions: validated value; external control ownership acquired
success: device acknowledgement/readback matches mapping; settling complete
failure: timeout / disconnected / rejected / mismatch; scan remains inhibited if control is required
observability: requested value, transmitted value, confirmed value, timestamp, device identity

Before implementation and hardware connection, obtain from the instrument documentation/vendor:

  • FiBDb235 control interface and protocol, connector type, and exact connector pin numbers.
  • Electrical limits: signal range, polarity, input impedance/current, ground/isolation, shielding, and any enable/interlock requirements.
  • Magnification mapping: supported values/range, voltage or command encoding, resolution, tolerance, and invalid-value behavior.
  • Timing/state behavior: update and settling time, readback/acknowledgement, error handling, and safe state.
  • Ownership: whether the microscope currently controls the box and how software control is enabled without conflicting with it.

The implementation sequence above is a design and commissioning plan, not a claim that the box is currently connected or controlled.

Before connecting hardware

  • Confirm the actual board revision and use its schematic to map FPGA balls to connector contacts. FPGA ball identifiers are not connector pin numbers.
  • Confirm the instrument-side OBI cable orientation, signal names, ground reference, and allowed I/O voltage. Do not connect based on this software mapping alone.
  • Compare the active streamData.json pin configuration with the table. It is checked in software by validate_obi_pin_config.
  • The host uses Glasgow USB pipes PQ, with the OUT FIFO for host commands and the IN FIFO for FPGA samples. These are USB pipes, not physical OBI connector pins.
  • Do not attach an external magnification signal to the DAC bus. Adding a separate scalar requires a new documented host command/register, FPGA receiver and a physically assigned pin or other defined instrument interface.
