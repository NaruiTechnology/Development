# Fail-safe blanking

Root cause of the black lines (field reports, 2026-10): the instrument's own
`BLANK`, generated by DSPB #1 and tied to the instrument's own scan, kept
blanking the ion beam while we scanned. The lines repeat with the
instrument's scan period, cover a fixed ~1.1 % of each period, and vanished
when the DSPB #1 cable (DSPB X6: L&F SYNC / BLANK / L&F RUN / ACB) was
unplugged and our X/Y injected into it.

That cable also carried `BLANK`. With it unplugged and no switch in its
place, nothing blanks the ion beam except the scan board. Upstream OBI
gateware drives **"beam on"** whenever it does not hold external control,
because it assumes a select switch then gives the column the instrument's
own blank. In the unplugged wiring, that leaves an unblanked ion beam parked
on one spot:

* before the first scan;
* between scans and after every scan;
* after Stop;
* if the host dies mid-scan.

That mills a pit within minutes.

## What the gateware does now

| Situation | Before | Now |
|---|---|---|
| FPGA loaded, no scan yet | beam on | **blanked** |
| Between scans, after a scan, after Stop | beam on | **blanked** |
| Takeover (switch delay) | blanked, except a 1-cycle glitch | blanked; host also sends Blank(on) first |
| Hand-back (switch delay) | blanked, except a 1-cycle glitch | blanked from the first cycle |
| Holding control, no new pixel for 100 ms (host crashed, service killed, USB stalled) | beam on, parked | **blanked** until the next pixel |
| USB unplugged or Glasgow without power | outputs 0 V: blank level undefined | **unchanged: hardware only, see below** |

The hand-back sequence itself is unchanged: after every scan, on Stop and on
errors the host sends Blank(on) → ExternalCtrl(off) → Synchronize, and the
select outputs (scan select A0/A1, blank select A4/A5) drop together. **These
outputs only hand anything back if a select switch is installed (below).**
With the DSPB #1 cable simply unplugged, nothing goes back to the instrument.

Remaining software windows:

* **On a stalled scan:** up to `stall_blank_ms` (100 ms) on one spot.
* **Host dead, Glasgow still powered:** the select outputs stay switched to
  the scan board. The watchdog blanks the beam, but nothing is handed back
  until the service restarts or the Glasgow loses power.

## What software cannot do

The Glasgow pull resistors follow pin inversion: while the Glasgow is
powered but the FPGA is not driving (bitstream load, reset), A3 is pulled
high and A2 low, which is "blanked", and A4/A5 are pulled high.

When the Glasgow loses power (USB unplugged, PC off), there are no pulls and
no drive: A2/A3 float. What the column then does depends on the receiver at
the far end. The DSPB X6 `BLANK` is an RS422 pair (`D1_BLNK±` into VDRV);
many RS422 receivers read an open pair as a fixed level, but not when the
line is terminated. **Measure it; don't assume it.** Only hardware can make
"scan board dead" mean "beam blanked":

1. **Replace the unplugged cable with a 2:1 switch** (recommended; it is what
   the software is written for):
   * input A (default, normally closed) = DSPB #1 (scan ramps and `BLANK`);
   * input B = scan board (X/Y and blank);
   * output = DSC / X62 (downstream);
   * select = `blank_enable` / `scan_enable` (A4/A5, A0/A1): high = scan board.

   Scan ramps are analog, so they need signal relays (G6K-2P-RF, TE IM23TS).
   The coils must be driven through a transistor or MOSFET from their own
   supply, not straight from Glasgow pins (a DC5 coil at 3.3 V is below its
   must-operate voltage). `BLANK` can use a logic 2:1 switch
   (74LVC1G3157, TS5A23157; RS422 receiver and driver if switched
   differentially). Give the select input a pull-down at the switch, so an
   unpowered Glasgow selects the instrument.

   With no power the switch falls back to the instrument, which blanks and
   scans the beam itself, and the instrument's own imaging works again.
2. **If the cable stays unplugged:** bias the receiver so an undriven pair
   reads "blanked", following the receiver's fail-safe resistor guidance,
   and verify it with step 5 below.

**Never** wire the scan board's blank in parallel with DSPB's `BLANK`
output. Two drivers fighting give an undefined level that works sometimes,
and can by itself produce intermittent black lines.

**Polarity:** with this patch the board's idle output is "blanked" = A3 high,
A2 low. If the pair is wired the other way round, idle becomes "beam on".
Step 1 of the verification checks this before anything else.

## Configuration

Both settings default on and need nothing in `streamData.json`. To set them
explicitly, add a block next to `timings`:

```json
"safety": {
    "blank_when_released": true,
    "stall_blank_ms": 100
}
```

* `blank_when_released: false` restores upstream OBI's "beam on" while
  released (and drops the forced blank while the switch moves). Use it only
  if the harness combines our blank with the instrument's *after* the select
  switch, so that our idle "blanked" would block the instrument's own
  imaging. With the 2:1 switch above, our blank is disconnected while
  released, and `true` changes nothing for the instrument.
* `stall_blank_ms`: 0 turns the watchdog off; at most 10000.
  * One pixel's dwell is at most about 8.2 ms, so 100 ms does not trip
    during a normal scan.
  * If the beam blanks during normal scans (USB pauses longer than 100 ms,
    e.g. on a virtual machine), the image will show a short dark band where
    the scan resumes. Raise the value rather than turning it off.

The FPGA image rebuilds on the next connection after the patch is applied,
so the first scan takes a few minutes longer.

## Verification on the tool

Watch the blank pair (A3 against A2) on a scope, or the column's blank
indicator:

1. Start the Glasgow service, before any scan. Expect **blanked**. If the
   beam is on, the blank pair is reversed: stop and fix the wiring first.
2. Run a short raster. Expect the beam on only during frames.
3. After the scan ends, and after pressing Stop mid-scan. Expect **blanked**,
   staying blanked.
4. During a long scan, kill the Glasgow service process (not Stop). Expect
   **blanked** within about 100 ms.
5. Unplug USB during a scan. This shows what your hardware does. Without the
   2:1 switch or receiver bias it is not guaranteed blanked. Do this step with
   the beam current at its lowest, or with the column valve closed.

Until step 5 passes, don't leave the ion beam on a sample unattended.
